# Gemma 4 31B on one RTX 4090

This guide builds, converts, verifies, benchmarks, and serves the text-only
`gemma4-31b-it/groupwise-int` target on one 24 GiB RTX 4090. Image, video, and audio input are not
supported. Do not pass `--vision`; media requests fail before model execution.

## Requirements

- Ubuntu 24.04 or a compatible Linux distribution;
- NVIDIA GeForce RTX 4090 and a current NVIDIA driver;
- CUDA Toolkit 12.8 or newer;
- GCC/G++ 13, CMake 3.28 or newer, Ninja, pkg-config, FFmpeg development libraries, and libcurl;
- Python 3.11, `uv`, and the Hugging Face `hf` CLI;
- approximately 25 GB for the immutable source checkpoints, 18 GB for the target-plus-assistant
  `.ninfer` artifact, and temporary conversion headroom.

The product runtime loads only `.ninfer`. GGUF and Hugging Face checkpoints are conversion or
comparison inputs, never runtime model artifacts.

## Build

Install native dependencies:

```bash
sudo apt-get update
sudo apt-get install --yes \
  build-essential gcc-13 g++-13 cmake ninja-build pkg-config \
  libavcodec-dev libavformat-dev libavutil-dev libswscale-dev \
  libcurl4-openssl-dev
```

Configure a Release `sm_89` build. Gemma is enabled by default; the option is shown explicitly so
the build contract is visible:

```bash
export CC=/usr/bin/gcc-13
export CXX=/usr/bin/g++-13
export CUDACXX=/usr/local/cuda/bin/nvcc
export CUDAHOSTCXX=/usr/bin/g++-13

cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_ARCHITECTURES=89 \
  -DNINFER_BUILD_GEMMA4_31B_IT=ON \
  -DNINFER_BUILD_APPS=ON \
  -DBUILD_TESTING=ON \
  -DNINFER_BUILD_BENCHMARKS=ON

cmake --build build -j 12
```

The main outputs are `build/apps/ninfer`, `build/apps/ninfer-serve`,
`build/bench/ninfer_bench`, and `build/bench/ninfer_gemma4_31b_it_retrieval`.

The repository Dockerfile also builds the `sm_89` applications:

```bash
docker build --tag ninfer-4090:sm89 .
```

## Acquire pinned sources

Use the exact revisions recorded below. The converter verifies the complete checkpoint SHA-256,
configuration, source inventory, tokenizer resources, and assistant inventory before writing.
Accept the upstream Gemma license and run `hf auth login` before downloading if the account has not
already been granted access.

```bash
hf download google/gemma-4-31B-it-qat-w4a16-ct \
  --revision 52f3f65bc7a02d555763bc923bd1d9094898219d \
  --local-dir models/source/gemma4-31b-target

hf download google/gemma-4-31B-it-assistant \
  --revision 627c5ec1458b9086b841a91e0512fd31fd2fbbf1 \
  --local-dir models/source/gemma4-31b-assistant
```

Expected single-checkpoint hashes:

```text

assistant/model.safetensors  9f80df6099fa1fd7db71220ec9ee864d5ecff769878697dd5763e4285b15a1da
```

## Convert the native artifact

Create an isolated Python 3.11 environment using the pinned dependency set. Do not install these
packages into NInfer's runtime or an unrelated project environment:

```bash
uv venv --python 3.11 /tmp/ninfer-gemma4-convert
uv pip install --python /tmp/ninfer-gemma4-convert \
  -r tools/reference/gemma4_31b_it/requirements.txt

/tmp/ninfer-gemma4-convert/bin/python \
  -m tools.convert.gemma4_31b_it.convert \
  --model models/source/gemma4-31b-target \
  --assistant models/source/gemma4-31b-assistant \
  --out models/gemma4_31b_it.ninfer \
  --device cuda
```

The converter writes both `models/gemma4_31b_it.ninfer` and
`models/gemma4_31b_it.ninfer.conversion.json`. Keep them together for release packaging. The report
contains the source revisions, source and artifact hashes, exact object inventory, transformations,
quantization metrics, environment, and command arguments.

For the pinned sources and converter revision qualified here, the target-plus-assistant artifact is
17,485,998,848 bytes with SHA-256:

```text
11d70c73f940930035516113a4b1cc25c685111692c4e9f2b345b430234ec83a
```

Omit `--assistant` for a smaller target-only artifact. That artifact runs ordinary generation but
correctly rejects `--spec mtp`.

## Verify

Run the complete C++ suite with the real artifact:

```bash
NINFER_GEMMA4_ARTIFACT=$PWD/models/gemma4_31b_it.ninfer \
  ctest --test-dir build --output-on-failure -j 1
```

For a shorter Gemma-only pass:

```bash
NINFER_GEMMA4_ARTIFACT=$PWD/models/gemma4_31b_it.ninfer \
  ctest --test-dir build --output-on-failure -j 1 \
  -R 'gemma4|heterogeneous_kv_cache'
```

The real Engine test covers public generation, deterministic sampling, ordinary/MTP parity,
multi-lane decode, cancellation, slot persistence, causal scoring, media rejection, graph
publication, wide chunks, and full-context MTP admission.

## Generate with the CLI

Target-only, short profile:

```bash
./build/apps/ninfer models/gemma4_31b_it.ninfer \
  --prompt "Explain why a sliding KV cache still needs absolute positions." \
  --max-context 8192 --max-new 256 \
  --prefill-chunk 1024 --kv-dtype rk4v4-e8 --greedy
```

Add the official assistant with the production one-draft selection:

```bash
./build/apps/ninfer models/gemma4_31b_it.ninfer \
  --prompt "Review this design and provide corrected C++ pseudocode." \
  --max-context 8192 --max-new 512 \
  --prefill-chunk 1024 --kv-dtype rk4v4-e8 \
  --spec mtp --draft-tokens 1
```

The registered sampling defaults are temperature 1.0, top-p 0.95, and top-k 64. Use `--greedy`
for exact argmax. Widths 1–6 are supported, but width 1 is the qualified production selection.

## Serve the full 262K profile

```bash
mkdir -p var/gemma4-slots var/gemma4-cache

./build/apps/ninfer-serve models/gemma4_31b_it.ninfer \
  --host 127.0.0.1 --port 8080 \
  --model-id gemma4-31b-it \
  --max-context 262144 --kv-capacity 262144 \
  --max-concurrency 1 --max-pending-requests 16 \
  --pending-timeout-ms 600000 \
  --prefill-chunk 1024 --kv-dtype rk4v4-e8 \
  --spec mtp --draft-tokens 1 \
  --slot-save-path var/gemma4-slots \
  --cache-dir var/gemma4-cache --cache-dir-max 32768 \
  --preserve-thinking
```

The full MTP1 profile leaves about 829 MiB available after startup on the qualified 24 GiB card.
Omit `--spec` to leave the assistant nonresident; the target-only profile leaves about 1.26 GiB.
The automatic persistent cache currently requires concurrency one. Its native snapshots include
both heterogeneous KV groups and are version/fingerprint/codec checked before restore.

Smoke-test the public API:

```bash
curl http://127.0.0.1:8080/health

curl http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gemma4-31b-it",
    "messages": [{"role": "user", "content": "Explain paged KV in one paragraph."}],
    "max_tokens": 128,
    "temperature": 0
  }'
```

Chat Completions, Responses, Anthropic Messages, streaming, health, metrics, slot controls, and
text prefix persistence all use the same public Engine. Media input returns HTTP 400
`vision_disabled`.

## Benchmark

Cold prefill and depth decode:

```bash
./build/bench/ninfer_bench \
  --weights models/gemma4_31b_it.ninfer --cycle-corpus \
  -p 4096,32768,65536,131072,196608,262016 \
  -r 1 --warmup 0 --max-ctx 262144 \
  --prefill-chunk 1024 --kv-dtype rk4v4-e8

./build/bench/ninfer_bench \
  --weights models/gemma4_31b_it.ninfer --cycle-corpus \
  -pg 262016,32 -r 1 --warmup 0 --max-ctx 262144 \
  --prefill-chunk 1024 --kv-dtype rk4v4-e8
```

Five-needle semantic retrieval at the native limit:

```bash
./build/bench/ninfer_gemma4_31b_it_retrieval \
  models/gemma4_31b_it.ninfer \
  --prompt-tokens 261120 --max-context 262144 \
  --prefill-chunk 1024 --generate 32
```

Success reports `missing_values=0 success=1`. The complete method, depth matrix, memory profile,
llama.cpp comparison, and profiler attribution are in the
[RTX 4090 performance report](benchmarks/gemma4-31b-4090-performance.md).

## Troubleshooting

- **Artifact identity rejected:** verify that the converter report says
  `gemma4-31b-it/groupwise-int` and container version 2.
- **Checkpoint hash mismatch:** download the pinned revision; do not substitute a GGUF, renamed
  shard set, or another Gemma size.
- **MTP objects missing:** regenerate with `--assistant`, or start without `--spec`.
- **Out of memory:** use one request, explicit 262,144 KV capacity, `rk4v4-e8`, 1,024-token chunks,
  and close other GPU processes. Do not enable Vision. A 2,048-token chunk consumes materially more
  workspace and is not the production default.
- **Persistent snapshot rejected:** artifact hash, codec, max-context layout, and speculative
  startup configuration must match the process that wrote it.
- **Slow MTP:** inspect accepted/drafted counters. All-rejected workloads are expected to be slower;
  rerun without `--spec` for that workload.
- **64K/128K prefill below llama.cpp:** this is a known measured limitation of the current Q4/A16
  and D512 routes, not a configuration error. NInfer leads the qualified comparison near 256K.
- **Python mismatch:** use an isolated Python 3.11 environment and the pinned requirements. The C++
  runtime has no Python dependency.

[artifact](maintainer/gemma4-31b-it-artifact.md),
[KV layout](maintainer/gemma4-kv-layout.md), and [MTP](maintainer/gemma4-mtp.md) references.
